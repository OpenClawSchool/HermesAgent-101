# Day 2. 에이전트 브랜딩과 상품화하기

## 오늘의 목표

> **누구나 처음 봐도 바로 이해하고 쓸 수 있도록 에이전트를 '상품'으로 포장(Packaging)합니다.**
>
> 오늘은 기능을 더 만들지 않습니다.
> 이미 만든 기능을 매력적인 이름·설명·입출력 정의로 다듬는 날입니다.

---

## 왜 중요한가

마켓에서 사용자는 에이전트의 내부 코드를 보지 않습니다. 사용자가 보는 것은 **이름, 아이콘, 소개 문구, 그리고 무엇을 넣으면 무엇이 나오는가**입니다.

아무리 좋은 에이전트라도 첫 화면에서 "이게 나한테 뭘 해주지?"라는 질문에 답하지 못하면 선택받지 못합니다.

### 좋은 상품화의 특징
- 이름만 봐도 무슨 일을 하는지 짐작된다.
- 새로운 사용자도 설명 한 번에 사용법을 안다.
- 입력값과 출력값이 명확해 기대치가 어긋나지 않는다.
- 첫 사용을 돕는 가이드(영상/문서)가 있다.

---

## 멘토 진행 가이드

멘토는 참가자에게 이렇게 안내합니다.

> "에이전트의 가치는 '무엇을 할 수 있는가'가 아니라
> '사용자가 그것을 이해할 수 있는가'에서 결정됩니다.
>
> 좋은 상품은 설명이 필요 없을 만큼 명확합니다."

이후 다음을 강조합니다.

> - **이름과 아이콘**: 서비스 성격을 한눈에 보여줄 것
> - **소개 문구**: 처음 온 사용자 기준으로 쓸 것
> - **입력/출력**: 무엇을 주면 무엇을 받는지 약속할 것
> - **가이드 영상**: 첫 사용자가 따라 할 수 있게 만들 것

---

## 참가자 미션 1. 브랜딩 세트 만들기

| 항목 | 작성 내용 |
| :--- | :--- |
| **에이전트 이름** | |
| **한 줄 슬로건** | |
| **아이콘/이미지 콘셉트** | |
| **일반 소개 문구(3줄)** | |

### 예시
- **이름**: 영수증 비서
- **슬로건**: 영수증 사진만 주면, 회계 정리는 끝.
- **아이콘 콘셉트**: 영수증 + 체크마크
- **소개**: "매일 쌓이는 영수증, 일일이 입력하지 마세요. 사진을 올리면 항목별로 분류하고 합계를 정리해 드립니다. 애매한 항목만 확인 요청을 드립니다."

## 참가자 미션 2. 입력값·출력값 정의하기

사용자와의 약속을 표로 정리합니다.

| 구분 | 내용 | 예시 |
| :--- | :--- | :--- |
| **입력값** | 에이전트가 작업하려면 받아야 하는 정보 | 영수증 이미지, 기간 |
| **출력값** | 의뢰자가 받게 될 결과물 | 항목별 분류표, 합계, 의심 항목 목록 |
| **처리하지 않는 것** | 범위 밖이라 명확히 선을 긋는 일 | 세무 신고 대행, 결제 |

## 참가자 미션 3. 첫 사용자 가이드 시나리오 짜기

가이드 영상/문서에 담을 흐름을 6단계로 적습니다.

```text
1. 이 에이전트는 누구의 어떤 문제를 푸는가
2. 무엇을 준비해야 하는가 (입력값)
3. 어떻게 요청하는가 (예시 명령)
4. 결과는 어떻게 생겼는가 (출력 예시)
5. 무엇은 사용자 승인이 필요한가
6. 자주 묻는 질문 / 주의할 점
```

---

## 오늘의 제출물

1. 브랜딩 세트 (이름·슬로건·아이콘 콘셉트·소개)
2. 입력값/출력값/범위 밖 정의표
3. 첫 사용자 가이드 6단계 시나리오
4. 가격 초안 (건당 수수료 + 월 구독료 가설)

> 💡 가격은 건당 수수료와, 그 약 10배 수준의 월 구독료를 함께 설계할 수 있습니다. 오늘은 확정이 아니라 가설만 적습니다. (상세 설계는 Day 4)

## 멘토 피드백 기준

| 기준 | 좋은 결과 |
| :--- | :--- |
| **이름이 직관적인가** | 이름·슬로건만으로 기능이 짐작된다 |
| **소개가 사용자 기준인가** | 개발자 용어가 아닌 사용자 언어로 쓰였다 |
| **입출력이 명확한가** | 무엇을 주면 무엇이 나오는지 어긋날 여지가 없다 |
| **범위를 그었는가** | 하지 않는 일을 분명히 해 기대치를 관리한다 |
