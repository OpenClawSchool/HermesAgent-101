# Day 1. 반복 업무 발굴하기

## 오늘의 목표

> **참가자가 매일, 매주 반복해서 확인하는 일을 찾아내고, 그중 에이전트 자동화에 적합한 후보를 고릅니다.**
>
> 오늘은 Heartbeat나 Cron을 바로 설정하지 않습니다.
> 먼저 자동화할 가치가 있는 업무를 찾는 날입니다.

---

## 왜 중요한가

많은 사람이 자동화를 시작할 때 “무엇을 자동화할지”보다 “어떤 기능을 쓸지”부터 봅니다.
하지만 에이전트는 사용자의 실제 환경에서 움직이는 실행형 어시스턴트이기 때문에, 기능보다 업무 반복성, 위험도, 승인 필요성을 먼저 따져야 합니다.

### 좋은 자동화 후보의 특징
- 자주 반복된다.
- 확인 기준이 명확하다.
- 실패해도 피해가 작다.
- 사람에게 보고만 해도 가치가 있다.
- 최종 실행 전에 승인을 받을 수 있다.

---

## 멘토 진행 가이드

멘토는 참가자에게 이렇게 시작합니다.

> "오늘은 자동화를 만들지 않습니다.
> 대신 내가 매번 확인하던 일을 찾아냅니다.
>
> 에이전트가 진짜 유용해지는 순간은
> 내가 앱을 여러 개 열어 확인하던 일을
> 채팅 한 번 또는 자동 점검으로 줄일 때입니다."

이후 다음 질문을 던집니다.

- 매일 아침 가장 먼저 확인하는 앱은 무엇인가요?
- 하루 중 반복해서 확인하는 정보는 무엇인가요?
- 놓치면 곤란하지만, 직접 확인하기 귀찮은 것은 무엇인가요?
- 매주 반복해서 정리하는 업무는 무엇인가요?
- AI가 실행하지 않고 알려주기만 해도 도움이 되는 일은 무엇인가요?

## 참가자 미션 2. 자동화 적합성 점수 매기기

각 업무를 1~5점으로 평가합니다.

### 평가 기준

| 평가 항목 | 설명 | 점수 |
| :--- | :--- | :---: |
| **반복성** | 얼마나 자주 반복되는가? | 1~5 |
| **기준 명확성** | 에이전트가 판단할 기준이 명확한가? | 1~5 |
| **시간 절약** | 자동화했을 때 시간이 줄어드는가? | 1~5 |
| **낮은 위험도** | 실패해도 피해가 작은가? | 1~5 |
| **승인 가능성** | 실행 전 사람이 검토할 수 있는가? | 1~5 |

## 멘토 피드백 포인트

> 💡 **주의 사항**
>
> 점수가 높아도 외부 발송, 삭제, 공유가 포함되면 자동 실행하면 안 됩니다.
> 에이전트가 먼저 요약하고, 사용자가 승인하면 실행하는 구조로 바꿔야 합니다.

## 멘토 피드백 기준

| 기준 | 좋은 결과 |
| :--- | :--- |
| **반복 업무가 실제적인가** | 참가자의 일상 업무와 연결되어 있다 |
| **자동화 후보가 안전한가** | 요약, 점검, 분류 중심이다 |
| **위험 작업을 구분했는가** | 발송, 삭제, 공유, 결제를 분리했다 |
| **채팅 중심 이점이 보이는가** | 앱을 열지 않고 지시·확인할 수 있다 |
