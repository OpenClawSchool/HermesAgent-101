# Day 3. Cron 예약 작업 설계하기

## 오늘의 목표

> **정해진 시간이나 주기에 실행할 에이전트 Cron 작업을 설계합니다.**
>
> 공식 문서 기준으로 Cron은 Gateway의 내장 스케줄러이며, 작업을 저장하고 정해진 시간에 에이전트를 깨워 실행하며 결과를 채팅 채널이나 웹훅으로 전달할 수 있습니다.

---

## 왜 중요한가

Cron은 “매번 내가 말하지 않아도 정해진 시간에 움직이는 비서”를 만드는 데 유용합니다.

**대표적인 예시:**
* **매일 08:30** - 아침 브리핑
* **매일 17:30** - 하루 마감 리포트
* **매주 월요일 09:00** - 주간 계획
* **매주 금요일 16:00** - 주간 회고
* **매월 1일** - 구독/정산 체크리스트

이렇게 설정하면 사용자는 여러 앱을 열어 확인하지 않고, 익숙한 채팅 채널에서 필요한 결과를 바로 받아볼 수 있습니다.

---

## 멘토 진행 가이드

멘토는 Cron을 설명할 때 **“시간이 중요한 작업”**이라는 점을 강조합니다. Cron은 정해진 시간에 실행되어야 가치가 있는 일에 적합합니다.

> **예를 들어:**
> * 아침 브리핑은 오전에 받아야 의미가 있고,
> * 회의 준비 알림은 회의 전에 와야 의미가 있고,
> * 주간 회고는 금요일 오후에 와야 의미가 있습니다.

---

## 참가자 미션 1. Cron 후보 찾기

아래 표를 채워 예약 가능한 Cron 후보를 발굴합니다.

| 예약 작업 | 실행 주기 | 실행 시간 | 결과물 | 왜 그 시간이 중요한가 |
| :--- | :---: | :---: | :--- | :--- |
| **아침 브리핑** | 매일 | 08:30 | 일정/메일/할 일 요약 | 업무 시작 전 필요 |
| **하루 마감 리포트** | 매일 | 17:30 | 완료/미완료/내일 할 일 | 퇴근 전 정리 |
| **주간 계획** | 매주 월요일 | 09:00 | 이번 주 우선순위 | 한 주 시작 전 필요 |
| | | | | |

## 참가자 미션 2. Cron 작업 상세 설계

아래 템플릿을 작성합니다.

```text
Cron 이름:

실행 주기:
(예: 매일 / 매주 월요일 / 매월 1일)

실행 시간:

에이전트가 확인할 정보:
(예: 캘린더, 이메일, 문서, 할 일 목록)

에이전트가 생성할 결과:
(예: 요약, 체크리스트, 회신 초안, 리스크 목록)

자동으로 해도 되는 일:
(예: 요약, 분류, 초안 작성)

승인이 필요한 일:
(예: 메일 발송, 일정 변경, 외부 공유)

결과를 받을 채널:
(예: Telegram, Slack, Discord, WhatsApp 등)
* 실제 지원 범위는 현재 공식 정보 기준으로 확인

실패했을 때 행동:
(예: 실행 실패를 알리고 재시도하지 않음 / 사용자에게 확인 요청)
```

---

## 예시 Cron 1. 매일 아침 브리핑

```text
Cron 이름: 매일 아침 운영 브리핑

실행 주기: 매일

실행 시간: 오전 8시 30분

에이전트가 확인할 정보:
오늘 캘린더, 최근 중요 메일, 마감일, 전날 미완료 작업

에이전트가 생성할 결과:
1. 오늘 일정 요약
2. 답장 필요한 메일
3. 마감 임박 작업
4. 오늘의 Top 3
5. 승인 필요한 작업

자동으로 해도 되는 일:
요약, 분류, 우선순위 제안

승인이 필요한 일:
메일 발송, 일정 변경, 파일 공유

실패했을 때 행동:
실패 사실만 알리고 자동 재시도하지 않음
```

---

## 예시 Cron 2. 매주 금요일 회고

```text
Cron 이름: 금요일 주간 회고 초안

실행 주기: 매주 금요일

실행 시간: 오후 4시

에이전트가 확인할 정보:
이번 주 일정, 완료한 일, 미룬 일, 답장 대기 메일

에이전트가 생성할 결과:
1. 이번 주 완료한 일
2. 미뤄진 일
3. 다음 주로 넘길 일
4. 반복 리스크
5. 다음 주 준비 항목

자동으로 해도 되는 일:
회고 초안 작성

승인이 필요한 일:
팀 채널 공유, 외부 발송
```

## 멘토 피드백 기준

| 기준 | 좋은 결과 |
| :--- | :--- |
| **시간성이 명확한가** | 그 시간에 실행되어야 하는 이유가 있다 |
| **결과물이 실용적인가** | 바로 행동할 수 있는 체크리스트다 |
| **승인 구조가 있는가** | 외부 발송·공유는 멈춘다 |
| **채널 활용이 자연스러운가** | 앱을 열지 않고 채팅에서 확인 가능하다 |
